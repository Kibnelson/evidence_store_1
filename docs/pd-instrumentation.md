# Request-level PD instrumentation

Use one measurement contract for 1P/3D and 2P/2D. For each request, identify GPU work actually scheduled, completed KV payload by path, and the wait before D can generate. The baseline and EvidenceStore must use the same event definitions. Reuse the earlier run cards for the request and routing joins and keep stock counters for independent reconciliation. [Earlier PD run review](../reports/prior-pd-review.md)

## Common events

Write one JSONL stream per worker or backend and a gateway stream that joins them. Every event carries `schema_version`, `run_id`, `topology`, `worker_id`, `role`, `host_id`, a local monotonic timestamp, and a sequence number. Request-level events carry stable `request_id`, `attempt_id`, and the worker's native request ID. Gateway events map those IDs to conversation and turn, the actual P and D, and the routing decision. Keep batch and transfer identifiers distinct from request identifiers. The run manifest records library and plugin pins, endpoint and device placement, visible tiers, clock offsets and uncertainty, and instrumentation flags.

| Event | Required payload and unit |
| --- | --- |
| Request and route | Arrival, admission, selection and queue exit timestamps. Chosen P and D and reason, conversation affinity, retargeting and fallback. Record P/D internal IDs and the connector's remote request ID. |
| Scheduled work | Phase, request and batch IDs, fresh prompt tokens, exact reuse, non-prefix reuse, repair positions and layers where available, and generated tokens. Preserve token ranges and the source of the observation. Record retries and recompute after failure separately. |
| GPU stage | Device, batch ID and its request membership, stage and GPU duration in ns. Include forward, repair/check, position correction, packing, copy, assembly, and generation when exposed. Keep FLOP estimates separate from measured GPU time. |
| Cache decision | Lookup tier and key/span identity, expected and actual hit, bytes and positions retrieved, compatibility and readiness, eviction or fallback reason. Log decision-time availability even if no bytes move. |
| Transfer attempt | Operation ID, attempt, backend and native handle, direction, source and destination worker/device/tier, purpose, submitted descriptor/tensor bytes, completed payload bytes, reported partial bytes and terminal status. Preserve per-rank/page/object details and transfer timings. Reuse one operation ID at both ends when tracing the same hop. |
| Physical link sample | Device/interface, link type, direction, scope, interval and counter delta. Track RDMA/NIC traffic, GPU peer traffic, host↔GPU copies and storage I/O with their applicable counters. |
| Serving milestone | P metadata ready, D transfer ready, D restore or assembly ready, first token, output-token timing, terminal result and output length. Use client timings for end-to-end TTFT. |

Use exact request counters for tokens and spans. GPU events or sampled Nsight/NVTX traces give batch/device timing. For mixed batches retain the request membership and per-request token work, with duration attributed to the batch. Overlapping CUDA intervals contribute only once to active time on a given GPU. Attribute per-request GPU durations on isolated probes or where the engine exposes a valid request-level stage. Keep stage durations available for overlap analysis. Use light telemetry for headline runs and compare it to instrumentation-off runs to measure overhead.

## Checks before a measurement is publishable

1. **Join and coverage.** Account for every sent request and its terminal state. Verify all three P→D pairs in 1P/3D and all four in 2P/2D. Report event coverage by role/backend and missing data per metric. Test a forced retry or fallback and confirm that it preserves the parent request ID and gets a new attempt.
2. **Bytes.** Calibrate an isolated full transfer against rounded KV block/tensor size and backend completion totals. Count completed payload once per operation and backend hop. Keep completed application payload, physical-link bytes, and local tier bytes visible as separate totals. A failed transfer with unreported delivered bytes has an unknown value. Reserve zero for an observed no-movement path. Compare NIC counters at link scope over aligned windows, recording host/device links and direction to avoid counting the same transmission twice.
3. **Compute.** Check a cold prompt, an exact prefix hit, and a reordered warm prompt with known spans. Verify that a reused span and a recomputed repair span are accounted for at the appropriate layer. Reconcile GPU activity with sampled traces, leaving batch-only timing at batch scope. Check PPD append-prefill separately from output-token work.
4. **EvidenceStore parity.** Use identical inputs, topology, quality thresholds, cache capacity by tier and routing policy for the paired baseline. Re-run the same isolated cases and natural traces. Include base creation, moves, recipe, patch, assembly, retries and asynchronous work through a declared drain point. Present P→D payload and total traffic by path alongside P and D compute, TTFT, TPOT, and goodput.
