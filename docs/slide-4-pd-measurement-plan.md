# EvidenceStore slide 4 measurement plan

Measure the KV work and data movement that remain after existing prefill/decode (PD) optimizations. First record what each baseline actually computes, reads, writes, and transfers. Then replay the same requests after adding EvidenceStore to measure how much of that work and traffic it removes, what it adds, and whether latency and goodput improve at matched quality.

Use the [earlier PD run review](../reports/prior-pd-review.md) for launch, routing, replay, and historical counter conventions. The [request-level instrumentation specification](pd-instrumentation.md) maps the required GPU work and movement events to vLLM, PPD, SGLang, and Mooncake source hooks.

The [native vLLM PD runbook](vllm-native-pd-runbook.md) implements B0 and its shared LMCache MP prefix-cache comparison. The B0 reference uses a full native NIXL handoff. The shared process serves P and D and keeps native D prefix reuse enabled. Each dataset's Faiss HNSW results carry document and chunk IDs and are frozen for paired replays.

## PD worker layouts

Use **1P/3D** as the default and **2P/2D** as a selectable topology. P is a prefill worker and D is a decode worker. Use the same four GPUs and start with one independent worker per GPU. The launch configuration selects the worker roles and supplies separate P and D endpoint lists to the gateway. Switch between runs by draining requests, reassigning one GPU, relaunching its worker, refreshing the routing table, and resetting and warming caches with the same trace. Record the effective host, GPU, NIC, and transport for each pair. Use distinct service and connector ports where workers share a host. ## What the blend settings enable
